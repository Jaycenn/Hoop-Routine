## Where AI-assisted work needed correction

1. **Unsafe seed behavior.** The earlier seed used conflict updates for workout metadata and drill-assignment positions; a later AI rewrite also raised the risk of replacing existing preset assignments. Running that against existing records could change a player's workout setup or ownership-related metadata. I required the revised seed to leave existing workout rows and assignments alone, stop on slug ownership conflicts, and pass preservation tests. The correction is in [Week 3 source](https://github.com/Jaycenn/Hoop-Routine/commit/46e84952da9b689d78a93ae821e006ad08b33b7f); the live seed was **not** run.

2. **Login tab styling mismatch.** Codex changed the login tab state to use aria-pressed while the CSS still targeted aria-selected. That could leave the selected tab styled incorrectly. The CSS selector was corrected in [Week 3 source](https://github.com/Jaycenn/Hoop-Routine/commit/46e84952da9b689d78a93ae821e006ad08b33b7f). This still deserves a final visual check.

3. **Outdated release documentation.** AI-assisted README and report text still said Week 3 source was uncommitted and a complete live-backed flow was unverified after the source commit and public API test. I had the documents corrected to state what was actually checked, including the difference between API tests and a full browser walkthrough. The correction is in the [documentation commit](https://github.com/Jaycenn/Hoop-Routine/commit/ef34e10761d7ab2cadc7cb3a33df4c5849976c6b).

## Who wrote what

The [September 24 foundation commit](https://github.com/Jaycenn/Hoop-Routine/commit/c92e28749b138fe2ac29ea2ebb850f9dd30e16b9) records my original Week 1 implementation. Specific examples I wrote and can explain:

- **client/src/App.jsx — ProtectedRoute:** I checked whether the account was still loading or signed in before displaying a workout page. An unsigned user goes to login so their private sessions are not shown in the interface.
- **client/src/pages/WorkoutPage.jsx — saveResult:** I gathered the drill form fields, sent the result to the session API, and advanced the flow. On the final drill, the page requested workout completion and handled save errors so the player knew what happened.
- **server/routes/sessions.js — normalizeResultBody and ownedSession:** I validated nonnegative result numbers, rejected makes greater than attempts, limited notes, and looked up a session using both its ID and the signed-in user's ID. The ownership check prevents one account from editing another account's session.
- **server/db/schema.sql — original tables and relationships:** I modelled accounts, workouts, drills, workout assignments, sessions, and results with keys and constraints so recorded work could be connected to the right player and workout.

These examples name original code, not an audited percentage of the **current** codebase. Later AI-assisted changes revised some of these files. I cannot honestly calculate the final manually written share from commits alone.

One piece Codex directly wrote is **server/lib/sessionOperations.js**, added in the [Week 3 source commit](https://github.com/Jaycenn/Hoop-Routine/commit/46e84952da9b689d78a93ae821e006ad08b33b7f). Its completion operation runs in a database transaction and locks the owned session row so two requests cannot finish it at the same time. If the session is already complete, it keeps the first finish time. Otherwise, it can save the final drill result, checks that at least one drill was completed, then stores the finish time and duration. An error rolls the transaction back. I kept this because it makes repeated or simultaneous save requests safer for the player's history.
